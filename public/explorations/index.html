Where this landed

Build this one: DASHBOARD

Round one put five directions up. BROADSHEET and WORKBENCH came out ahead — the paper-and-ink look, and the snap-in windows. Round two fuses them, two different ways, because there are exactly two honest answers to "windows, but printed".

PRESS ROOM keeps WORKBENCH's mechanics literally: loose sheets on a light table, free geometry, overlap allowed, edge snapping, saved arrangements. Maximum flexibility. COMPOSITOR refuses to let anything overlap — the viewport is a page and panes are set into it, rearranged by swapping and by pulling gutters. Nothing ever hides behind anything, and the page is always full.

COMPOSING ROOM put both on a radio: arrange sheets freely when you are thinking, lock the page up when you are working. DASHBOARD is that engine wearing the real app's clothes — the retractable sidebar, Dashboard / List / Calendar / Reports / Settings, panels you can resize from any edge or corner. It is the production candidate: drop it in where the four stat cards are today.

Serve them, don't double-click

They will open straight off the filesystem, but Chrome restricts localStorage on file://, so changes will not survive a refresh. Any static server fixes it: 

npx serve .

Shared state is deliberate

All five read and write the same localStorage key. Complete a task in TERMINAL and it is complete in PULSE. That is the point — it is one app wearing five faces. Reset in any variant restores the seed for all of them.

Nothing is loaded from the network

No CDN, no web fonts, no three.js. Every shader is hand-written WebGL, every chart is hand-drawn canvas or SVG. These files work on a plane.

Where the logic lives

_kernel.js — the data model, the store, the event log, and all the derived intelligence. The variants contain no business logic at all. Porting a winner means keeping the kernel and rewriting one file.
